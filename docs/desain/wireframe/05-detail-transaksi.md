\# WIREFRAME 05 — DETAIL TRANSAKSI



\## Sistem Informasi Laundry Koin



\### 1. Tujuan Halaman



Halaman Detail Transaksi digunakan oleh Pemilik dan Admin/Operator untuk melihat informasi lengkap dari transaksi yang dipilih.



\### 2. Sketsa Wireframe



```text

+----------------------------------------------------------+

| SISTEM INFORMASI LAUNDRY KOIN           Pengguna | Logout|

+----------------------------------------------------------+

| Dashboard | Transaksi | Layanan | Laporan                 |

+----------------------------------------------------------+

|                                                          |

|  DETAIL TRANSAKSI                                        |

|                                                          |

|  ID Transaksi   : TRX-001                                |

|  Tanggal        : DD-MM-YYYY                              |

|  Nama Pelanggan : Nama Pelanggan                          |

|  Layanan        : Nama Layanan                             |

|  Total Biaya    : Rp 00.000                                |

|                                                          |

|  ----------------------------------------------------    |

|                                                          |

|  \[ Kembali ke Daftar Transaksi ]                          |

|                                                          |

+----------------------------------------------------------+

```



\### 3. Komponen Halaman



| No. | Komponen | Fungsi |

|---|---|---|

| 1 | Header | Menampilkan identitas sistem dan pengguna |

| 2 | Navigasi | Menampilkan menu sesuai hak akses |

| 3 | Judul Halaman | Menunjukkan halaman Detail Transaksi |

| 4 | ID Transaksi | Menampilkan identitas transaksi |

| 5 | Tanggal | Menampilkan tanggal transaksi |

| 6 | Nama Pelanggan | Menampilkan pelanggan terkait transaksi |

| 7 | Layanan | Menampilkan layanan yang dipilih |

| 8 | Total Biaya | Menampilkan biaya transaksi |

| 9 | Tombol Kembali | Mengarahkan pengguna ke daftar transaksi |



\### 4. Anotasi



1\. Halaman menampilkan informasi berdasarkan transaksi yang dipilih.

2\. Informasi transaksi ditampilkan dalam susunan yang mudah dibaca.

3\. Pemilik dan Admin/Operator dapat melihat rincian transaksi.

4\. Tombol Kembali digunakan untuk kembali ke Daftar Transaksi.

5\. Data yang ditampilkan bersumber dari transaksi yang telah tersimpan.



\### 5. Prinsip Desain



\- Keterbacaan: informasi disusun secara teratur.

\- Konsistensi: label dan format data dibuat seragam.

\- Efisiensi: informasi penting dapat dilihat dalam satu halaman.

\- Kejelasan: setiap data memiliki label agar mudah dipahami.



\### 6. Catatan



ID transaksi dan data yang ditampilkan pada sketsa hanya contoh. Nilai sebenarnya diambil dari data transaksi yang tersimpan dalam sistem.
