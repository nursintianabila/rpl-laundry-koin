# 4.5 Rilis dan Dokumentasi

Rilis pertama aplikasi diberi nomor versi 1.0.0 mengikuti Semantic Versioning MAJOR.MINOR.PATCH. Nomor versi didefinisikan sekali di `versi.py` dan ditampilkan pada kaki halaman melalui variabel global Jinja2, sehingga pengguna dapat memastikan versi yang sedang dipakai. Anotasi Git tag `v1.0.0` telah dibuat dan didorong ke repositori; tag ini menjadi rujukan tetap untuk demo dan peninjauan, dan tidak boleh dipindahkan bila kemudian diterbitkan versi tambalan 1.0.1. Ringkasan perubahan tersimpan pada `CHANGELOG.md` bagian `## [1.0.0]` yang memuat fitur, perbaikan hasil pengujian, dan perbaikan keamanan.

| Aspek rilis | Nilai / bukti |
|---|---|
| Versi | 1.0.0 (`versi.py`) |
| Tag Git | `v1.0.0` (anotasi) |
| Server produksi | Waitress 3.0.2 pada port 8000 |
| Variabel wajib | `APP_ENV=production`, `SECRET_KEY`, `TOKO_DB` |
| Basis data | SQLite pada lokasi `TOKO_DB` |
| Cadangan | `cadangan/laundry_koin-YYYYMMDD-HHMMSS.db` |

Dokumentasi pengguna disiapkan dalam dua berkas utama. README pada akar repositori menjelaskan deskripsi, fitur, kebutuhan, instalasi, tabel variabel lingkungan, pembuatan akun pertama, cara menjalankan aplikasi pada mode pengembangan dan produksi, pengujian, serta struktur proyek. Manual pengguna pada `docs/manual-pengguna.md` memuat sembilan tugas dalam bahasa klien, mulai dari masuk ke aplikasi hingga mencari transaksi, dilengkapi tabel "Bila ada masalah" yang berisi pesan galat yang benar-benar muncul pada aplikasi. Prosedur pencadangan dan pemulihan dijelaskan terpisah pada `docs/cadangan.md`, sedangkan langkah deployment dan keputusan `COOKIE_SECURE` tercatat pada `docs/deployment.md`. Rincian konfigurasi dan bukti audit kesiapan rilis tersedia pada `docs/audit-rilis.md`.

Uji produksi dilakukan dengan menjalankan Waitress pada `127.0.0.1:8000` dengan `APP_ENV=production` dan `SECRET_KEY` yang diatur melalui variabel lingkungan; halaman login berhasil dibuka dan menampilkan versi 1.0.0. Sebagai uji negatif, aplikasi sengaja dijalankan tanpa `SECRET_KEY` dan menolak start dengan pesan "SECRET_KEY wajib diisi pada mode produksi." Uji cadangan dan pemulihan juga berhasil: data yang dihapus kembali setelah berkas cadangan disalin ke lokasi basis data. Seluruh perintah tersebut menjadi dasar penulisan README, bukan dugaan.
