# 4.2 Implementasi Sistem

Aplikasi dibangun dengan arsitektur berlapis yang memisahkan tanggung jawab setiap bagian. Lapisan Routes menerima permintaan HTTP dan meneruskan proses ke Services; lapisan Services memuat aturan bisnis dan validasi; lapisan Models menjadi satu-satunya tempat perintah SQL ditulis; lapisan Views berupa templat Jinja2 yang mewarisi `templates/base.html`. Pemisahan ini memudahkan peninjauan karena perubahan tampilan tidak menyentuh logika basis data, dan sebaliknya. Berikut struktur folder utama beserta perannya.

| Folder / berkas | Peran |
|---|---|
| `app.py` | Membuat aplikasi Flask, mendaftarkan blueprint, memuat konfigurasi lingkungan |
| `models.py` | Koneksi SQLite, `PRAGMA foreign_keys = ON`, seluruh query tabel |
| `services/` | Validasi layanan, pelanggan, transaksi, dan autentikasi |
| `routes/` | Rute untuk modul auth, layanan, pelanggan, dan transaksi |
| `templates/` | Templat induk dan halaman per modul |
| `static/css/` | Satu berkas gaya tampilan |

Fitur utama yang diimplementasikan meliputi login dengan dua peran, pengelolaan layanan dan harga, pengelolaan pelanggan, pencatatan transaksi dengan total biaya otomatis, serta pencarian dan penyaringan transaksi. Potongan kode berikut menunjukkan perhitungan total biaya di lapisan service: harga layanan diambil dari basis data melalui `models.ambil_layanan`, lalu dikalikan berat dan dibulatkan. Perhitungan ini sengaja tidak dipercayakan kepada formulir karena harga merupakan data rancangan yang harus konsisten dengan tabel `layanan`.

```python
def tambah_transaksi(id_pelanggan, id_layanan, tanggal, berat):
    nilai, galat = periksa_isian(id_pelanggan, id_layanan, tanggal, berat)
    if galat:
        raise ValidasiTransaksiError(galat)
    layanan = models.ambil_layanan(nilai["id_layanan"])
    total_biaya = int(round(nilai["berat"] * layanan["harga"]))
    return models.tambah_transaksi(
        nilai["id_pelanggan"], nilai["id_layanan"],
        nilai["tanggal"], nilai["berat"], total_biaya,
    )
```

Tiga siklus prompt representatif dari jurnal menunjukkan proses kerja yang terkendali. Siklus pertama meminta kerangka proyek; hasil AI menempatkan kunci rahasia di kode sehingga keputusan diubah dengan memindahkannya ke variabel lingkungan. Siklus kedua meminta daftar layanan; hasil akhir diperbaiki agar SQL tetap berada di `models.py` dan tombol tambah tidak menaut ke rute yang belum ada. Siklus ketiga meminta form tambah dengan validasi; AI menghasilkan alamat `action` yang ditulis langsung, lalu diubah menjadi parameter agar dapat dipakai ulang oleh form ubah. Contoh terakhir termasuk kategori yang menunjukkan bahwa tinjauan manusia diperlukan meskipun kode tampak berjalan.
