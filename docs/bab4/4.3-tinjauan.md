# 4.3 Tinjauan Kode dan Keamanan

Tinjauan kode dilakukan pada dua level. Pertama, latihan tinjauan terhadap berkas `kasus_rentan.py` yang sengaja mengandung sepuluh kelemahan; hasilnya ditulis pada `docs/laporan-temuan.md`. Kedua, tinjauan terhadap kode proyek sendiri dengan daftar periksa Lampiran C Jobsheet 11 dan 12, menghasilkan sekurangnya lima temuan yang tercatat pada `docs/temuan-keamanan.md`. Kategori temuan memakai OWASP Top 10:2025 agar rujukannya jelas, meskipun beberapa temuan masuk kategori keterbacaan atau kebenaran, bukan keamanan murni. Setiap temuan diberi status diperbaiki atau ditunda beserta alasannya, sehingga tidak ada temuan yang hilang tanpa keputusan.

| ID | Temuan | Kategori | Status | Bukti perbaikan |
|---|---|---|---|---|
| T-01 | Query SQL dirakit dengan f-string pada login (kasus latihan) | A05 Injection | Diperbaiki | Query berparameter di `models.py` |
| T-02 | Hapus data lewat GET tanpa login | A01 Broken Access Control | Diperbaiki | POST + dekorator peran + CSRF |
| T-03 | Kata sandi di-hash dengan MD5 tanpa garam | A04 Cryptographic Failures | Diperbaiki | `generate_password_hash` Werkzeug |
| T-04 | Catatan dapat dibaca pengguna lain | A01 Broken Access Control | Diperbaiki | Filter kepemilikan pada query |
| T-05 | Kunci rahasia dan debug mode terbuka | A04 / A02 | Diperbaiki | `SECRET_KEY` dari lingkungan, debug sesuai `FLASK_DEBUG` |
| T-06 | Token CSRF belum ada | A01 | Diperbaiki | Token per sesi, pengecekan `before_request` |
| T-07 | Batas percobaan login belum ada | A07 | Diperbaiki | 5 kegagalan per 5 menit, respons 429 |

Contoh sebelum dan sesudah perbaikan terlihat pada validasi kata sandi. Sebelumnya kode latihan memakai `hashlib.md5(p.encode()).hexdigest()`, yang menghasilkan nilai sama untuk kata sandi sama dan cepat dihitung ulang. Setelah perbaikan, aplikasi memakai `check_password_hash` dengan hash dari `generate_password_hash`, yang menyertakan garam otomatis. Pemeriksaan manual terhadap kolom `password_hash` di basis data menunjukkan awalan `scrypt:`, sesuai bukti pada `tests/test_rilis.py`. Temuan yang ditunda yaitu cookie Secure untuk HTTP jaringan tertutup dan constraint UNIQUE pada nama layanan; keduanya dicatat pada `docs/triase-temuan.md` dengan alasan dan sprint tujuan.
